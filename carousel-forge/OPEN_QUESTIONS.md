# OPEN_QUESTIONS

M0·M1을 구현하며 사양이 정해지지 않았던 지점들이다. 임의로 추정하지 않고
여기에 적은 뒤 **기본값으로 진행**했다. 각 항목에 "지금 어떻게 해뒀는지"와
"바꾸려면 어디를 고치면 되는지"를 함께 적는다.

기준일: 2026-08-18 · 범위: M0, M1

---

## 1. 이 저장소와 기존 앱의 관계

`project_0001`에는 이미 `insta-content-studio`(Next.js)가 있다. Carousel Forge는
같은 문제를 훨씬 넓게 다루므로, 흡수인지 대체인지 공존인지가 정해져 있지 않다.

- **기본값**: 기존 앱을 건드리지 않고 `carousel-forge/` 하위에 독립적으로 만들었다.
- 통합 방향이 정해지면 `apps/web`(M8)에서 기존 UI 자산을 가져올 수 있다.

## 2. 중국어 폰트가 아직 임베드돼 있지 않다

Pretendard(한/영)만 `core/render/fonts/`에 들어 있다. Noto Sans SC는 파일이
크고 M7(샤오홍슈·중국어) 전에는 렌더에 쓰이지 않는다.

- **기본값**: `scripts/fetch_fonts.py --set zh`는 지금은 라이선스 파일만 받는다.
  중국어 세트를 실제로 쓰려면 `core/render/model.py`의 `FONT_FILES`에 등록해야 한다.
- 등록되지 않은 폰트를 쓰려 하면 렌더가 조용히 대체 폰트로 넘어가지 않고 실패한다.

## 3. Figma가 로컬 폰트를 못 찾을 때의 동작

SVG는 `font-family` 이름으로 **보는 사람 컴퓨터의 폰트**를 찾는다. Pretendard가
설치돼 있지 않으면 Figma가 임의로 대체하면서 줄바꿈이 달라진다.

- **기본값**: 내보내기 ZIP의 `04_reference/fonts/`에 폰트를 동봉하고, `README.md`에
  "먼저 폰트를 설치하라"를 첫 단계로 적었다. `manifest.json`의 `fonts_required`에도
  같은 정보가 들어 있다.
- M6 플러그인 경로에서는 `figma.loadFontAsync` 실패를 잡아 사용자에게 알릴 수 있다.
  SVG 드래그앤드롭 경로에는 그런 훅이 없다.

## 4. text-transform을 SVG에 어떻게 실을 것인가

StyleDNA의 `case: upper`는 CSS `text-transform`으로 렌더된다. 화면에는 대문자,
DOM에는 원문이 남는다.

- **기본값**: **화면에 보이는 글자**(변환된 텍스트)를 SVG와 manifest에 싣는다.
  그래야 PNG와 어긋나지 않는다.
- 대안: 원문을 싣고 Figma `textCase = 'UPPER'`로 재현. 편집 시 원문이 보존되는
  장점이 있으나 SVG 경로에는 대응 속성이 없다. 어느 쪽이 편집 경험에 나은지 미정.
- **부작용**: `emphasis_spans`의 인덱스는 원문 기준이다. 한국어·영문 대소문자
  변환은 길이가 보존되지만, 길이가 변하는 문자(예: ß → SS)가 들어오면 인덱스가
  어긋난다. 현재 대상 언어(ko/zh/en)에서는 발생하지 않는다.

## 5. SVG 경로에서 텍스트를 길게 고치면 줄바꿈이 따라오지 않는다

SVG의 각 줄은 실측 좌표가 박힌 `<tspan>`이다. Figma에서 문구를 늘리면 그 줄만
길어지고 자동으로 다음 줄로 넘어가지 않는다.

- **기본값**: 이 한계를 `README.md`에 적지 않았다 — 대신 **플러그인 경로(M6)를
  권장 경로로 안내**한다. 플러그인은 TextNode에 전체 문자열과 폭을 주므로 Figma가
  스스로 줄바꿈한다.
- SVG 경로는 "가볍게 문구 다듬기"용, 플러그인 경로는 "제대로 편집"용으로 나뉜다.

## 6. 배경 이미지 위 대비 검증이 아직 픽셀 기반이 아니다

`core/render/geometry.py`는 WCAG 대비비와 스크림 합성 계산을 제공하지만, 배경이
사진일 때 **텍스트 뒤 실제 픽셀 휘도**를 샘플링하지는 않는다.

- **기본값**: M1은 안전영역 침범(기하)만 판정한다. 대비 판정은 A8/A9가 붙는 M4의 일이다.
- 그때 필요한 것: 렌더 페이지에서 각 텍스트 박스 영역의 평균/최악 휘도를 캔버스로
  샘플링하는 측정 항목 추가.

## 7. 캔버스 variant가 데이터 모델에 없다

`RenderSet.canvas_variant`로 `square` 같은 대체 캔버스를 고를 수 있지만,
`CarouselSet` 테이블에는 대응 컬럼이 없다.

- **기본값**: 항상 플랫폼 기본 캔버스를 쓴다. variant를 실제로 노출할 때
  마이그레이션을 하나 더 얹는다.

## 8. platforms.yaml의 수치는 사람이 확인해야 한다

`scripts/validate_platforms.py`는 **형태**(비율 일관성, 범위, 필수 필드)만 본다.
1080×1350이 오늘의 인스타그램 규격이 맞는지는 검증하지 못한다.

- **기본값**: `_meta.verified_at`에 확인일을 적고, 180일이 지나면 `/healthz`와
  검증 스크립트가 경고한다. 갱신은 사람이 각 플랫폼 문서를 보고 한다.

## 9. 업로드용 이미지 기본 포맷이 JPG다

`platforms.yaml`의 `export_format` 첫 항목이 쓰인다. 인스타그램은
`["jpg", "png"]`이라 기본이 JPG(품질 95)다.

- **기본값**: JPG. 파일이 작고 업로드가 빠르다.
- 무손실이 필요하면 `export_format` 순서를 뒤집으면 된다. 코드 변경은 필요 없다.

## 10. `summary` role은 스펙 본문이 아니라 부록 B에만 있다

섹션 3.2의 `slide_roles_sequence` 예시에는 없지만 부록 B의 role 표에는 있고,
A4가 "마지막 직전에 저장 유발 요약본"을 배치하라고 요구한다.

- **기본값**: 스키마의 `SlideRole` enum에 포함시키고, 레이아웃은 `point` 템플릿에
  매핑했다. 요약 전용 템플릿이 필요하면 M4에서 4번째 템플릿을 추가한다.

## 11. Playwright 브라우저 리비전이 환경과 어긋난다

이 환경에는 Chromium 1194가 깔려 있고 playwright 1.62는 1234를 기대한다.

- **기본값**: `core/render/html_renderer.chromium_executable()`이
  `PLAYWRIGHT_BROWSERS_PATH`의 실행 파일을 직접 찾아 쓴다.
  `CAROUSEL_FORGE_CHROMIUM`으로 명시 지정할 수도 있다.
- CI에서는 브라우저 리비전을 고정해야 렌더 결과가 재현된다. 조판 엔진이 바뀌면
  실측 좌표도 미세하게 달라진다.

## 12. 출력 배율(device scale factor)이 1로 고정돼 있다

`SlideRenderer(device_scale_factor=...)`로 바꿀 수 있으나 파이프라인은 1을 쓴다.

- **기본값**: 1080×1350 실측 픽셀. 플랫폼 규격 자체가 그 크기라 업스케일이
  이득인지 불분명하다. 2x가 필요하다는 근거가 나오면 그때 올린다.

## 13. 폰트 재배포의 법적 검토

Pretendard는 SIL OFL 1.1이라 임베드·재배포가 가능하고, 내보내기 ZIP에
`Pretendard-LICENSE.txt`를 함께 넣는다.

- **기본값**: 동봉한다. 다만 결과물이 외부 사용자에게 전달되는 형태이므로
  실제 서비스 전에 법무 확인을 권한다. OFL이 아닌 폰트는 절대 동봉하지 않는다
  (절대 규칙 #10).

## 14. 폐기본 보존의 범위

절대 규칙 #9는 "모든 생성물은 DB에 남긴다(폐기본 포함)"이다.

- **기본값**: `Asset.is_discarded`/`discard_reason`과 `GenerationLog`로 **레코드**를
  남기고, `storage/` 실물 파일은 `.gitignore`에 넣었다(버전 관리 대상이 아님).
  파일 보존 기간·용량 정책은 정해지지 않았다.

## 15. 픽셀 대조에서 남는 1% 차이

`scripts/verify_render.py`가 PNG와 SVG 래스터를 비교하면 글자 영역에서 약 1%의
픽셀이 다르게 나온다.

- **원인**: 서브픽셀 안티에일리어싱과 JPEG 압축. 정수 픽셀 이동 탐색에서 9장 모두
  최적 이동이 `(0,0)`이므로 좌표가 밀린 것은 아니다.
- **기본값**: 불일치 비율 상한 2.5%, 그리고 **최적 이동이 (0,0)이 아니면 실패**.
  후자가 좌표 회귀를 잡는 진짜 지표다.

## 16. 거절(refusal) 시 서버측 폴백을 아직 켜지 않았다

Opus 5는 정책상 요청을 거절할 수 있고(`stop_reason: "refusal"`), 그때 같은 요청을
다른 모델로 자동 재시도하는 서버측 `fallbacks` 파라미터가 있다.

- **기본값**: 끔(`config/models.yaml`의 `llm.fallbacks_enabled: false`).
  현재는 거절이 오면 `LLMRefusalError`로 **명시적으로 실패**한다.
- **이유**: API 키가 없어 이 경로를 한 번도 실행해 보지 못했다. 검증하지 않은
  베타 파라미터를 기본 경로에 넣으면, 정작 거절이 났을 때 폴백이 아니라 400이
  날 수 있다. 키가 생기면 켜고 실제로 확인한 뒤 기본값을 바꾼다.

## 17. LLM 프로필이 전부 Opus 5다

`config/models.yaml`의 세 프로필(reasoning/drafting/cheap)이 모두 `claude-opus-5`고,
작업의 무게는 `effort`(high/medium/low)로만 구분한다.

- **기본값**: 모델은 고정, effort로 조절. 비용 때문에 모델 등급을 낮추는 것은
  사용자가 결정할 일이라 임의로 내리지 않았다.
- 낮추고 싶으면 `profiles.<이름>.model`만 바꾸면 되고 코드는 손댈 필요가 없다.
  단, Haiku 계열은 `effort`를 지원하지 않으므로 함께 지워야 한다.

## 18. M0의 models.yaml에 Opus 5에서 제거된 파라미터가 있었다

최초 작성 시 `temperature`를 넣어 뒀는데, Opus 5는 `temperature`/`top_p`/`top_k`와
`thinking.budget_tokens`를 모두 400으로 거부한다. M2 작업 중 발견해 `effort`로
교체했고, 회귀를 막는 테스트(`test_config_has_no_removed_sampling_params`)를 붙였다.

## 19. 상태 머신 순서와 마일스톤 순서가 어긋난다

파이프라인은 INTAKE → STYLE_RESOLVE → RESEARCH → FACTCHECK → ARCHITECT → COPY
순인데, M2에서 만든 것은 INTAKE·ARCHITECT·COPY다. 그 사이의 A1(M3)·A3/A6(M5)이
아직 없어서 전체 오케스트레이터로는 M2 결과를 볼 수 없다.

- **기본값**: M2 산출물은 `scripts/demo_m2.py`가 세 에이전트를 직접 이어 확인한다.
  스펙의 마일스톤 순서를 그대로 따랐고, 순서를 바꾸지 않았다.
- M5까지 붙으면 오케스트레이터 한 줄로 전 구간이 돌아간다.

## 20. 키워드 각도 선택이 자동이다

A2의 키워드 경로는 각도 3개를 제안하고 사용자가 고르는 것이 스펙이다. 하지만
파이프라인이 끝까지 돌아야 완료 기준을 확인할 수 있어서 지금은 자동 선택한다.

- **기본값**: 0번(첫 번째)을 고르고 `angle_auto_selected: true`를 상태에 남긴다.
  제안 3개도 함께 남기므로 `--angle N`으로 다시 돌릴 수 있다.
- UI가 붙으면(M8) 여기서 사용자 선택을 받는다.

## 21. A2의 키워드 경로가 리서치 없이 각도를 만든다

스펙은 "확장 리서치로 각도 3개 제안"이라고 적혀 있지만 리서치 프로바이더는 M5다.

- **기본값**: 모델의 내부 지식만으로 각도를 제안한다. 그래서 각도의 시의성
  ("왜 지금")은 검증되지 않은 추정이다.
- 같은 이유로 URL 인테이크도 아직 막혀 있다. M5에서 web_search/web_fetch가
  붙으면 두 경로가 함께 열린다.

## 22. 축약 3회 후의 "더 큰 텍스트존" 교체가 제한적이다

스펙: "3회 시도 후에도 초과하면 레이아웃 템플릿을 더 큰 텍스트존으로 교체".
M1의 템플릿은 hook/point/cta 셋뿐이고, 그중 여유가 가장 큰 것은 point다.

- **기본값**: hook·cta는 point로 옮기고 마지막 1회를 더 시도한다. 이미 point인
  슬라이드는 옮길 곳이 없으므로 **명시적으로 실패**한다(조용히 통과시키지 않는다).
- 글자수 상한 자체는 템플릿을 바꿔도 그대로다 — StyleDNA의 하드 제약이기 때문이다.
  템플릿 교체가 늘려 주는 것은 렌더 시 안전영역의 여유다.
- 요약 전용 템플릿을 M4에서 추가하면 옮겨 갈 자리가 하나 더 생긴다.

## 23. StyleDNA 추출이 동기 실행이다

스펙의 `POST /styles/extract`는 비동기 job이다. 작업 큐(Celery/Redis)는 아직 없다.

- **기본값**: 동기 실행. 6장 기준 1분 남짓 걸리는 요청이 된다.
- 없는 큐를 흉내 내는 가짜 job id를 돌려주느니 오래 걸리는 요청으로 두는 편이
  정직하다. 큐가 붙으면 이 엔드포인트만 바꾸면 된다.

## 24. 벤치마크 피드가 커버만 담고 있다

M3 왕복 검증에 쓰는 피드는 게시물마다 **커버 한 장**이다. 그래서 두 가지를 못 본다.

- **본문 텍스트가 없다** → `body.size_ratio`를 관찰할 수 없어 모델이 부제 크기를
  본문 크기로 읽는다 (0.032 → 0.021).
- **여백이 넓어 미니멀해 보인다** → 정답 라벨은 `infographic-dense`인데 모델은
  `editorial-minimal`로 읽는다. 커버만 보면 그렇게 보이는 게 맞다.
- **기본값**: 그대로 둔다. 측정 층 검증이 목적이고 그쪽은 8/8이다. 해석 층까지
  제대로 재려면 게시물당 여러 장을 렌더하는 피드가 필요하다.

## 25. 이미지 분석에 Pillow를 쓴다

금지 사항은 "이미지 위에 텍스트를 굽는 Pillow 기반 렌더링"이다. 여기서 Pillow는
**픽셀을 읽는 데만** 쓴다 — 팔레트 k-means와 경사 기하 계산의 입력이다.

- 글자를 그리는 경로는 여전히 브라우저뿐이다. 검증 렌더의 비교 시트조차 HTML로
  만들어 Playwright로 찍는다.

## 26. 텍스트 영역 판정이 OCR 없이 경사에 기댄다

글자가 있는 곳은 국소 대비가 급격히 오른다는 성질만 쓴다. 그래서 사진 배경처럼
대비가 큰 이미지가 섞이면 텍스트가 아닌 곳을 잉크로 셀 수 있다.

- **기본값**: 임계값을 분위수와 최대 에너지 대비 하한의 큰 쪽으로 잡고, 대비가
  아예 없으면 "못 쟀다"고 보고한다(추정하지 않는다).
- 사진 배경 계정에서 오차가 커지면 그때 텍스트 검출기를 붙인다. 지금 넣으면
  검증할 방법이 없다.

## 27. 이미지 프로바이더가 절차적 생성 기본값이다

`config/models.yaml`의 1순위는 Higgsfield지만, 이 환경에서는 파이썬 프로세스가
Higgsfield MCP를 직접 부를 수 없다.

- **기본값**: `ProceduralProvider` — 팔레트에서 그라디언트 + 그레인 배경을 만든다.
  글자가 없고, 텍스트가 얹힐 영역을 저정보 영역으로 비운다는 성질은 지킨다.
  외부 크레딧 없이 루프 전체가 돌기 때문에 버그를 먼저 잡을 수 있다.
- 실제 생성물을 넣으려면 `FileProvider`로 디렉터리를 지정한다. 파이프라인은 배경의
  출처를 모르므로 어느 쪽이든 그대로 돈다.
- `HiggsfieldProvider`는 아직 NotImplementedError다. MCP 브리지나 HTTP 키가 생기면
  그때 붙인다 — 검증할 수 없는 호출 코드를 미리 써 두지 않는다.

## 28. A9의 비전 판정이 합성본이 아니라 배경을 본다

"이미지 안에 글자가 있는가"를 합성본으로 물으면 **우리가 얹은 글자**가 잡힌다.

- **기본값**: 배경 원본만 비전 모델에 넣는다. 배경에는 글자가 없어야 하고, 그게
  판정의 대상이다.
- 대신 합성 후에만 보이는 문제(글자가 배경의 복잡한 부분에 걸침 등)는 비전이 아니라
  기하 판정(대비·오버플로)이 잡는다.

## 29. identity_drift를 아직 판정하지 않는다

`quality_rules.yaml`의 blocking 목록에 있지만 A9는 아직 검사하지 않는다.

- **이유**: 슬라이드 간 인물 얼굴 비교는 여러 장을 한 번에 보고 판단해야 하는데,
  현재 절차적 배경에는 인물이 없어 검증할 대상이 없다. 검증할 수 없는 판정을
  넣으면 통과하는지 아닌지 알 수 없는 코드가 된다.
- 인물이 있는 배경을 실제로 생성하게 되면 그때 붙인다.

## 30. 크레딧 소진으로 M4의 모델 경로를 실행하지 못했다

M4 작업 중 Anthropic API 크레딧이 소진됐다. 그래서 다음 둘은 **코드는 있지만 실제
호출로 검증하지 못했다.**

- `ArtDirector.plan()` — 모델이 세트 전체의 조명·팔레트와 슬라이드별 장면을 짜는 경로
- `QualityGate`의 비전 판정 — "이 이미지가 AI 생성물로 보이는가"

- **대신 검증한 것**: `plan_from_briefs()`(A4의 visual_brief로 프롬프트를 짜는 경로)와
  기하·규칙 판정, 그리고 폐기·재생성 루프 전체. 루프는 모델 없이도 도는 부분이 본체다.
- 크레딧이 충전되면 위 두 경로를 실제로 돌려 확인해야 한다.
